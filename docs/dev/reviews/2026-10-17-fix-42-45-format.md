## #42: `%5%`

- **Change**: a flag, width or precision inside the `%%` escape is E0826,
  in lowering (analog) and in the digital engine's format walk; codegen
  asserts it never meets one.
- **Reading**: §9.4.1/Table 9-21 (and IEEE 1364-2005 Table 17-1) define
  `%%` as two characters; C11 7.21.6.1p8 says "The complete conversion
  specification shall be %%", so `%5%` is undefined in C and §9.4.3's C
  grant gives it nothing. Refused rather than read as a literal `%`.

| Module | Error set | Boundary validation | Check budget | Bounds |
| ------ | --------- | ------------------- | ------------ | ------ |
| `ir` `lower/systask.zig` | `Oom` (unchanged) | the literal format is source input: `%<prefix>%` is E0826, never an assert | none new | `nextConv` unchanged |
| `backend` `cg_display.zig` | `Error` (unchanged) | none: lowering refused it, and lowering errors stop the pipeline before codegen (`Lower.lowerFile`) | `assert(conv != '%')` after the prefix | unchanged |
| `sim` `digital/display.zig`, `rt/system.zig` | `Error` (unchanged) | E0826 (`failWith`) when the walk validates; a held run-time format ends the run | none | unchanged |

| Bug class | Oracle | Layer | Tier | Harness / file |

`%`s; the old table only had `100%%`.
