# Design review: #42 to #45, §9.4 format specifications

Four bug fixes found during #41, one commit each. §10.1: a bug fix runs R6
and R7 (the missing oracle, Principle 19.4).

- **Domain skill(s)**: `compiler-construction` (FIXTURES.md); `api-design`
  for #44 (`tools/contract.zig` ships to hosts).
- **Hot/cold**: cold. Format scanning runs once per display call at compile
  time; the device kernels and the digital formatter run when text prints.

## #42: `%5%`

- **Change**: a flag, width or precision inside the `%%` escape is E0826,
  in lowering (analog) and in the digital engine's format walk; codegen
  asserts it never meets one.
- **Reading**: §9.4.1/Table 9-21 (and IEEE 1364-2005 Table 17-1) define
  `%%` as two characters; C11 7.21.6.1p8 says "The complete conversion
  specification shall be %%", so `%5%` is undefined in C and §9.4.3's C
  grant gives it nothing. Refused rather than read as a literal `%`.

| Module | Error set | Boundary validation | Check budget | Bounds |
| ------ | --------- | ------------------- | ------------ | ------ |
| `ir` `lower/systask.zig` | `Oom` (unchanged) | the literal format is source input: `%<prefix>%` is E0826, never an assert | none new | `nextConv` unchanged |
| `backend` `cg_display.zig` | `Error` (unchanged) | none: lowering refused it, and lowering errors stop the pipeline before codegen (`Lower.lowerFile`) | `assert(conv != '%')` after the prefix | unchanged |
| `sim` `digital/display.zig`, `rt/system.zig` | `Error` (unchanged) | E0826 (`failWith`) when the walk validates; a held run-time format ends the run | none | unchanged |

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| lowering and codegen disagree on a prefixed `%%` | hand table: `%5% %-% %.%` → three `%` letters, prefixed | unit | merge | `systask.zig` test "§9.4.3 nextConv" |
| a prefixed `%%` accepted | E0826 pinned, reject-only | fixture | merge | `s01_20_percent_escape_with_width_rejected.va`, `b_17_1_1_1_percent_escape_with_width_rejected.v`, `display.zig` test "a malformed format" |

The missing oracle was a `nextConv` case with something between the two
`%`s; the old table only had `100%%`.

## #44: a `%g` precision on the host

- **Change**: `tools/contract.zig` `cReal` renders a `%g` with an explicit
  precision as `%f` at that precision, the text `str_kernels.zCReal` prints.
- **Reading**: §9.4.3's example ("%10.3g ... three (3) fractional digits")
  against C11's significant digits. VerA chose the example on the device
  (`zCReal`, `s01_01`'s withdrawn rows); the host now agrees. The other way,
  both C11, would change device text that fixtures and users already see,
  against the LRM's printed example. Recorded in `Vague_Decisions.md` §6.
- **Boundary (R1)**: `formatSay` is a host-called entry point. Its
  signature, `Say`/`SaySite` layout and `abi_version` are unchanged; the
  text it writes for `%.<p>g` changes, which the CHANGELOG bullet says. A
  host that wants C's reading has no switch for it: none is added, since
  the device it renders never prints C's text either.

| Module | Error set | Boundary validation | Check budget | Bounds |
| ------ | --------- | ------------------- | ------------ | ------ |
| `contract` `tools/contract.zig` | `std.Io.Writer.Error` (unchanged) | none new | none | the precision is still cut to 64 (`formatC`); the `%f` path's 512-byte scratch holds 309 digits + 64 |

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| host and device text differ for one format | hand-derived `%f` text, asserted against both `zCReal` and `formatSay` | unit | merge | `lib/backend/kernels/test.zig` "a %g precision: the device's zCReal and the host's formatSay print one text" |

The missing oracle (Principle 19.4) was a test that holds the device kernel
and the host renderer to one expected string; each had its own table.

## #43: C flags in the digital context

- **Change**: one prefix reader, `src/sim/fmt.zig` `spec` (flags from
  `str_kernels.zcFlag`, then width and precision), and one rule,
  `fmt.flagVerdict`, read by the interpreter's format walk, the native
  emitter and the native run-time scanner of held formats. Real conversions
  render every C flag (`display.real` passes them to `zCReal` and streams
  the field's padding); other conversions refuse '-', '+', ' ' (E0827) and
  '#' (E0825).
- **Reading**: IEEE 1364-2005 §17.1.1.2 grants C to Table 17-3's real
  conversions; §17.1.1.3 sizes the rest and names only the zero override,
  so a leading '0' there stays a width digit (`%0d`, `%05d` width 5, as
  before). Refused rather than accepted and ignored (AGENTS §4).

| Module | Error set | Boundary validation | Check budget | Bounds |
| ------ | --------- | ------------------- | ------------ | ------ |
| `sim` `fmt.zig` | none (pure) | none: callers judge `flagVerdict` | none | `spec` saturates width and precision, as the scanners it replaces did |
| `sim` `digital/display.zig` | `Error` (unchanged) | a literal format's flags are judged when `walk` validates (E0825/E0827, `failWith`); a held format's when the task runs | none | `real` writes the padding, never buffers it |
| `sim` `rt/system.zig` | `Error` (unchanged) | `scanSpec` ends the run on a refused flag (the same rule) | none | unchanged |
| `sim` `digital/emit.zig` | `Error` (unchanged) | none: `walk` validated the literal format first | none | unchanged |

| Bug class | Oracle | Layer | Tier | Harness / file |

| digital transcript | hand-derived C11 text | fixture | merge | `ieee1364/17_system_tasks/b_17_1_1_2_real_c_flags.v`; refusal `b_17_1_1_2_c_flag_on_integer_rejected.v` |

The missing oracle (Principle 19.4) was a digital-engine run under C's
flags: the flag sweep of `printf_reference.zig` reached `zCReal` only, which
the digital path called with flags 0.

## #45: an over-large width or precision

- **Change**: lowering's `nextConv` reads each conversion's width and
  precision (saturating) and `prepareFormatArgs` refuses either past
  `max_format_field` = 2^30, E0828; `cg_display`'s scratch sums saturate.
- **Limit**: 2^30, from the device: `zCReal` indexes digit positions as i32
  (precision + 309 integer digits + rounding position), and a field's
  scratch is width + precision + 328 bytes. Recorded in
  `Vague_Decisions.md` §7, whose string-row entry no longer claims every
  width is accepted.

| Module | Error set | Boundary validation | Check budget | Bounds |
| ------ | --------- | ------------------- | ------------ | ------ |
| `ir` `lower/systask.zig` | `Oom` (unchanged) | a literal format's width and precision are source input: past 2^30 is E0828, a diagnostic | none new | `nextConv`'s numbers saturate at maxInt(u64) |
| `backend` `cg_display.zig` | `Error` (unchanged) | none: lowering bounds the fields, and lowering errors stop the pipeline | none new (no assert on an outside value) | `scratch` saturates; a saturated row is `fits`'s E1011 |

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| a width/precision overflow reaches codegen arithmetic | 2^30 accepted, 2^30 + 1 and a 23-digit width refused, by hand | unit | merge | `systask.zig` test "system tasks: arguments a task refuses" |
| the field `nextConv` reads | hand table (width vs precision, '0' as flag and digit, saturation) | unit | merge | `systask.zig` test "§9.4.3 nextConv" |
| refusal in a whole compile | E0828 pinned, reject-only | fixture | merge | `s01_21_format_field_past_its_limit_rejected.va`, neighbour `sformat_field_width_over_4096.va` |

The legal neighbour AT the limit is the unit test, not a fixture: a device
field of 2^30 is a gigabyte of static scratch and a gigabyte of text.

Exit criteria (all four): `zig build test` exits 0; the new fixtures
(`s01_19`, `s01_20`, `s01_21`, `b_17_1_1_1_percent_escape_with_width_rejected.v`,
`b_17_1_1_2_real_c_flags.v`, `b_17_1_1_2_c_flag_on_integer_rejected.v`) pass
and their VERDICTS.tsv rows match; the FAIL/XFAIL name lists are unchanged.
