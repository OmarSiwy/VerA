# Design review: #75, discipline resolution cubic in the instance count

- **Change**: `resolve.resolveMultiCandidates` groups a net's arrivals into
  §7.4.1 levels once per net (`levelsOf`), and `resolveLevel` visits only its
  level's members, so Annex F.2.1 step 4 is linear in the arrivals instead
  of cubic. Results are unchanged.
- **Domain skill(s)**: `compiler-construction`, `data-oriented-design`.
- **Hot/cold**: cold pass with a measured super-linear blow-up. Evidence:
  issue #75's profile (64% in `resolveLevel`, 54% in the inlined `levelOf`,
  ReleaseSafe, N = 1024) and the timings below.
- **Stages run**: R6, R7 (bug fix, §10.1).

## Root cause

`resolveMultiCandidates` called `resolveLevel(i)` once per undeclared
arrival (memoized). Every call walked all of the net's arrivals and called
`levelOf` for each one, and `levelOf` is an O(arrivals) `startsWith` scan
over the paths. For a top with N instances of a module whose port has no
discipline, one net gets 2N arrivals and N levels: N · 2N · 2N.

## Data (R2)

| Table | Owner | Fields: width (range) | Layout | Capacity | Lifetime/arena | Producer → consumer |
| ----- | ----- | --------------------- | ------ | -------- | -------------- | ------------------- |
| `Levels` (one per net with a step-4 question) | `resolve.zig` | `start: []u32` (arrival offsets, ≤ arrivals), `members: []u32` (arrival index < arrivals), `probes: u32` | CSR: level g is `members[start[g]..start[g+1]]`, level `arrivals` the net's own | arrivals + 2 offsets, arrivals members; arrivals ≤ u32 (`@intCast`, same as the `resolved` memo's u32 key) | `ctx.arena`, the elaboration's | `levelsOf` → `resolveLevel` |

Transforms:
- `levelsOf: Segs.paths → Levels` (a path → first-index map, then one
  hash lookup per `sep` of each path from the longest proper prefix down,
  then a stable counting sort by level).
- `resolveLevel: Segs, Levels, resolved → resolved, signal_disciplines`.

Identity with the old order: a level's members stay in arrival order (the
counting sort is stable) and the call structure is unchanged, so every
`levelAnswer`, diagnostic and `noteSignalDiscipline` append happens in the
same order as before. `levelOf`'s tie rule (the first arrival among equal
paths) is the map's first-index rule.

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `elab` `resolve.zig` | `Error` (unchanged; `OutOfMemory` from the arena) | none: paths are built by the walk, not read from outside | new assert in `resolveDiscipline`: every arrival path is empty or ends in `sep` (the premise of `levelsOf`'s prefix search); one in `levelsOf`: the offsets cover every arrival | `levelsOf`'s inner loop runs once per `sep` of a path plus once for the empty prefix |

## Test plan (R7)

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| a level different from the old rule | `levelOf`, the old O(n) scan, kept as the oracle | unit | merge | `resolve.zig` test `levelsOf` |
| a return to super-linear work (#75) | prefix-lookup count: exactly 3 per instance of #75's shape at N = 256, doubling at 512 and 1024; every arrival in one level (so `resolveLevel` visits each once) | unit | merge | `resolve.zig` test `levelsOf` |
| resolution answers moved | `--emit-zig` stdout+stderr+rc of the before and after binaries over every `.va` under `tests/fixtures` (2648 files) | differential | one-off | this review |
| goldens moved | `zig build golden -- diff` | golden | gate | coordinator |

The missing oracle (Principle 19.4) was a work count: no test bounded how
many arrivals a net's resolution looks at. The `probes` count is it, read
without a clock.

## Measurements

`vera --emit-zig` on #75's reproducer (`safe-03.va`, one net, N instances of
`mid` with an undeclared port, each with a `leaf`), ReleaseFast, one run at a
time, wall clock:

| N | before (3777de35) | after |
| ---- | ------- | ------- |
| 256 | 0.085 s | 0.009 s |
| 512 | 0.508 s | 0.013 s |
| 1024 | 3.811 s | 0.020 s |
| 2048 | 34.252 s | 0.034 s |

stdout and stderr are byte-identical between the two binaries at every N,
and over all 2648 `.va` under `tests/fixtures` (`--emit-zig`, 0 diffs).

Exit criteria: `zig build test` exits 0 (the `levelsOf` test runs there);
`zig build golden -- diff` prints IDENTICAL; the fixture name lists do not
move.
