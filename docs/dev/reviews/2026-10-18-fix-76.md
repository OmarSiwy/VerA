# Design review: #76, a card write through an `aliasparam` does not set the parameter

- **Change**: the device's `derive` folds a §3.4.7 alias the host wrote onto
  the original parameter with its value AND its `__given` flag, so §9.19
  `$param_given` reads 1 and §6.3.4's dependent default no longer erases the
  value.
- **Domain skill(s)**: `compiler-construction` (codegen), `api-design` (the
  card is a host boundary; its shape is unchanged).
- **Hot/cold**: cold. `derive` runs once per card write, never per `eval`.
- **Stages run**: R6, R7 (bug fix, §10.1).

## Root cause

`emitDerive` (`lib/device/codegen/file.zig`) wrote
`if (model.trise__given) model.dtemp = model.trise;` and then, for a
parameter whose default reads another parameter,
`if (!model.dtemp__given) model.dtemp = model.a;`. The host raises the
ALIAS's flag (`trise__given`), never the original's, so the second line
overwrote the card's value with the default and `$param_given(dtemp)` read 0.

Every host path reaches the alias the same way: it writes the `Model` field
named on its card and that field's `__given` (`tb/runner.zig` `setCard` for
`//! param`/`//! psweep`, `tools/osdi_dyn.zig` `overlay`), then calls
`derive`. `derive` is the only place an alias is resolved for a card
(`grep aliases lib tools src`: `plan/names.zig` names the field,
`file.zig` `emitModel` declares it, `emitDerive` folds it), so the fix there
fixes every host once. Hierarchy overrides (`#(.trise(5))`) fold at
elaboration and were already right.

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `device` `codegen/file.zig` `emitDerive` | `Error` (unchanged) | none new: the card is the host's, and the flag write is unconditional on the alias's flag | no runtime check added; the device text gains one store per alias whose original has a `__given` | one line per `Lowered.aliases` row |

The `__given` store is emitted only where `plan/names.zig` gave the original a
flag (`Names.p_given`: a `derive` target or a `$param_given` operand); a
parameter with neither has no flag to set and nothing reads one.

| OSDI host (ngspice `.model ... trise=5`) | same `derive`; `osdi_dyn.overlay` raises the alias's flag as before | n.a. | — | covered by the shared `derive`; no separate test |

The missing oracle (Principle 19.4): no fixture wrote a card through an alias
onto a parameter with a dependent default or a `$param_given` query
(`07_parameter_alias.va` writes `trise` onto a constant-default `dtemp` and
reads only the value). The new fixture is that oracle.

Exit criteria: the fixture passes with 4 verdicts; the unit test passes under
`zig build test`; goldens move only in `derive` of devices with an alias whose
original has a `__given` flag.
