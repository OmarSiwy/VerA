# Design review: #79, `--emit-osdi` of a module with no parameters does not build

- **Change**: `tools/osdi_dyn.zig`'s `access` and `givenModel` return "no
  slot" / 0 before indexing `Model.given`/`vals` when the device has no §3.4
  parameter, so those zero-length arrays are never analysed against a runtime
  index.
- **Domain skill(s)**: `api-design` (the OSDI boundary), `zig` (comptime
  pruning).
- **Hot/cold**: cold. Parameter access runs at card time; the guard is a
  comptime-known condition and costs nothing in a device with parameters.
- **Stages run**: R6, R7 (bug fix, §10.1).

## Root cause

With `np == 0` and an `Instance.mfactor` (every VerA device has one),
`num_inst_params = num_params = 1`. `access`'s model branch
`id >= num_inst_params and id < num_params` is not comptime-false, so Sema
analysed `m.given[j]` and `&m.vals[j]` over `[0]bool`/`[0]u64` and refused it
("cannot index into empty array", lines 597 and 604 of #79). The instance
branch (`id < np`) and `givenInstance` fold to false at comptime and were
fine; `Ev` in the tests has neither parameters nor `$mfactor`, so its
`num_params == 0` folded the model branch away too, which is why the unit
tests never saw it.

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `osdi_dyn` `access`, `givenModel` | C ABI: null / 0 for an id with no slot (unchanged contract) | the id is the simulator's; an id with no model slot returns null/0 as before | none new: `np == 0` is comptime | n.a. |

Verified before commit (one build, no other running): `vera --emit-so --dyn
tools/osdi_dyn.zig` over #79's reproducer builds with this file and fails
with the pre-fix file at 597:29 and 604:40, the issue's two errors.

The missing oracle (Principle 19.4): no OSDI test instantiated a device with
`$mfactor` and no parameter. `NoParam` is that device.
