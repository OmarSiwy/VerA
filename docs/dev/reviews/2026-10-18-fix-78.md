# Design review: #78, x-dependence that ignored a `?:` condition

- **Change**: `Analysis.xDep`/`pointDep` (the `xdeps`/`pdeps` columns) count
  what steers a value without entering its derivative: a select's condition,
  an array load's or store's index, and the branches that pick a phi's
  incoming edge. The derivative columns (`deps`, `acdyn`) keep the arm-only
  rule. The post-dominator tree moves from `setup.postDominators` into
  `Analysis.ipdom` (a separate, output-neutral commit) because the phi rule
  needs it.
- **Domain skill(s)**: `compiler-construction`.
- **Hot/cold**: cold (a compiler pass). The emitted device text changes for
  affected devices only.
- **Stages run**: R6, R7 (bug fix, §10.1).

## Root cause

`fixDeps` used one rule set for every column. For `.ternary` it was
`deps(then) | deps(else)`, right for the derivative (`S.sel` passes the taken
arm's lanes through) and wrong for "does this value move with x": a select
over two constants on a probe condition is 2 at one bias and 3 at another.
`.load` dropped its index and `.phi` dropped the branches that choose its
edge for the same reason. Two consumers read the wrong fact:

- `codegen/family.zig` `constant()`: `Lattice.card` (`!xDep`) treated the
  select as a card constant, so `V * (V > 0.4 ? 2 : 3)` was "affine" and the
  device declared `constant.g = true`; `steered` missed a branch on a flag
  set by a `?:`.
- `cg_limit.zig`'s E0527 check (`xDep(seed)`) accepted a seed that reads the
  solution only through a condition.

`render.zig`'s `perPoint`/`host_expr.zig` (through `lanes.perPoint` →
`pointDep`) had the same blind spot: a probe-steered select over constants
rendered as `.scale(sel.val())`, one point's value in a batch family.

## The rule

For the `steered` columns (`value`, `point`):

- `select(c, a, b)`: `c | a | b`.
- `load(arr, i)`: `arr | i`; `store(arr, i, v)`: `arr | i | v`.
- `phi` in block `b`: its incoming values, plus every condition in
  `steer_pool[b]`: each branch whose immediate post-dominator is `b` (where
  its arms rejoin), and, when `b` is a loop header, every branch inside its
  outermost nest (how many times round decides which value leaves).

Why the immediate post-dominator and not `plan/topology.zig`'s "branch at the
join's immediate dominator": a `break` makes a loop exit a join whose
immediate dominator is the header, while the `if` around the `break` also
picks its edge; that `if`'s ipdom is the exit. Lowering's CFGs are otherwise
structured (one join per diamond, `lowerCaseChain` nests its joins), so an
inner branch's ipdom is the inner join and its steering reaches the outer
phi through the inner phi, which keeps the rule as narrow as the old one
everywhere x does not steer. `topology.constFree` stays: it asks a stronger
question (constant over the whole simulation: no time, no state, an
allowlist of calls) and only its comment changed.

## Data (R2)

| Table | Owner | Fields: width (range) | Layout | Capacity | Lifetime/arena | Producer → consumer |
| ----- | ----- | --------------------- | ------ | -------- | -------------- | ------------------- |
| `ipdom` | `Analysis` | `u32` block index (< nb, or nb = virtual exit) | one column, nb + 1 | nb + 1 | `Analysis.arena` | `buildPostDominators` → `setup.controlDeps`, `plan/core.zig`, `buildSteer` |
| `steer_pool`/`steer_off` | `Analysis` | `Mir.Value` (a branch condition); `u32` offsets | CSR per block | one entry per branch plus one per (branch in a nest, header of that nest) | `Analysis.arena` | `buildSteer` → `defDeps` phi rule |

Transforms:
- `buildPostDominators: succs, preds → ipdom` (moved verbatim from setup).
- `buildSteer: term, rpo, ipdom, is_loop, loop_of → steer_pool, steer_off`.
- `fixDeps(.value | .point): defs, steer_pool → xdeps | pdeps`.

`xdeps` is now always its own column (it was `deps`'s slice unless a `dstop`
existed): one more nv-word fixpoint per compile.

The missing oracle (Principle 19.4) was a differential one: no test compared
a `constant` claim with the device at a second bias where a condition flips.
`const_check` exists and is always on; what was missing was a fixture whose
second bias crosses a condition. The three fixtures above are that, with the
bias chosen so the flip holds for any unknown index (`x' = 1.5 x - 0.25 -
0.125 i` puts `V(p)` at or below -0.25 from 0, past the -0.1 threshold).

Checked with the pre-fix ReleaseFast binary (`--emit-zig`): the three
fixtures declare `constant.g = true` (and `.c = true` for the capacitance),
and the seed fixture compiles with rc 0. The post-fix runs happen at the
final gate.

Exit criteria: `zig build test` exits 0 (the three unit tests run there);
the five fixtures pass under `zig build benchmark -- --strict`; no other
fixture enters the FAIL list.

## What moves

The refactor commit (`Analysis.ipdom`) is output-neutral: goldens IDENTICAL.
The fix commit changes device text only where x steers a value whose arms do
not vary: `constant` tables (to false), `zMulP`/`zAddP` in place of
`scale`/`addC` of such a value, host-expression fallbacks
(`host_expr.zig`), and possibly `batch_ok`/lane pinning. Every device
without such a value keeps its text.
