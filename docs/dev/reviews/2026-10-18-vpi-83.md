# Design review: #83, SystfHost for an external host

- **Change**: three additions so a host that is not VerA's own analog walk
  (ESPice, ESPice#197) can run a VPI application's analog calltf through
  VerA's `vpi` module: `contract.Systf.task` (V1), `vpi.analog_run.setPoint`
  (V4), and a named `NOSOLUTION` refusal from `vpi_get_analog_value` when the
  attached `Lib` holds no slot of the quantity (V5). V2/V3 are #84.
- **Domain skill(s)**: `api-design` (the contract table and the `vpi`
  module's Zig face), `compiler-construction` (lowering → codegen fact).
- **Hot/cold**: cold. `Systf` rows are a comptime table; `setPoint` runs once
  per analysis point; `quantityValue` once per application call. No loop over
  many elements, no profile.
- **Stages run**: R1, R6, R7, R9 (a boundary change, §10.1); R10 by reading.

## Boundary (R1)

The usage code an external host writes, first. It compiles the device
itself, so it reads `systf_calls` at comptime; it loads the user's VPI
application into VerA's `vpi` module and runs each call through it.

```zig
const contract = @import("contract");
const vpi = @import("vpi");
const D = @import("device"); // the --emit-zig output

// V1: refuse, on an .hdl cache hit where nothing is compiled in-process, a
// value-position `$name` the application registered as a task (or none).
for (D.systf_calls, 0..) |c, k| {
    const want: c_int = if (c.task) vpiAnalogSysTask else vpiAnalogSysFunc;
    if (registeredType(c.name) != want) return refuse(k, c.name, c.task);
}

// V5's stub: the device library's call table, no solution in it.
try vpi.analog_run.attach(.{
    .n_u = zero, .n_rows = zero, .n_shares = zero, .x = emptyX,
    .systf = keepHooks, // receives the HostCall/HostOut VerA hands out
    .n_systf = nSystf, .systf_name = systfName, .systf_tok = systfTok, .systf_outs = systfOuts,
    .open = unused, .solve = unused, .accept = unused, .row = unused, .rows = unused,
    .shares = unused, .ac = unused,
});

// V4: inside the host's own Newton loop, before the device's eval reaches
// `inst.systf.?.call(ctx, k, args, partials)`:
vpi.analog_run.setPoint(.{ .kind = .tran, .start = 0, .stop = tstop, .max_step = hmax }, t, h, 0);
// … AC point: setPoint(.{ .kind = .ac, .fstart = f0, .fstop = f1 }, 0, 0, f)
// … between analyses: setPoint(null, 0, 0, 0)
```

The signatures:

```zig
// tools/contract.zig
pub const Systf = struct { name: []const u8, tok: u32 = maxInt(u32), outs: u64 = 0, task: bool = false };
// src/vpi/analog.zig (vpi.analog_run)
pub fn setPoint(a: ?Analysis, t: f64, dt: f64, f: f64) void;
pub fn attach(l: Lib) error{OutOfMemory}!void; // unchanged
```

The five characteristics:

- **Granularity**: `setPoint` sets the four values §12.7-§12.9 and §12.18
  read, as one call, because they change together at a point; a host cannot
  leave `delta` stale while moving `t`. `Analysis` rather than the issue's
  bare `kind`: `vpi_get_real` reads its bounds, and a kind alone would make
  them read 0 silently. `.{ .kind = .tran }` is still a one-field literal.
- **Redundancy**: none added. `task` is a fact codegen already had
  (lowering marks the call); VerA's own host does not need it (it has the
  source) and its C `Lib` interface is unchanged.
- **Coupling**: `task` is read at comptime from the device a host already
  imports; `setPoint` adds no type. The stub `Lib` reuses the existing
  `Lib`: no second interface for a calls-only host.
- **Retention**: VerA's walk keeps its state as before; `setPoint` is now
  its one writer of `current`/`t_now`/`delta`/`freq` (`run`, `attempt`,
  `sweep`, `detach` call it), so an external host and VerA's walk set the
  point through the same door.
- **Flow control**: the host's. It calls `setPoint` and then the device's
  eval; VerA calls back only into the application's calltf.

Integration discontinuity: a host can use VerA's whole walk (`run`), or its
own walk with VerA's calls (`setPoint` + `attach` of a stub), with no cliff
between: the stub is the same `Lib` with four functions replaced.

`abi_version`: unchanged (6). `tools/contract.zig` marks every new
defaulted field of a published table "Additive: no `abi_version` change"
(`Systf.outs`, `SystfHost.out`, `checkCard`), and an old device without
`.task` reads as a function, which is what every pre-#83 device's
consumer assumed. A host that must tell an old device from a new one has
nothing to go on; that is the cost of not bumping, and the same cost
`outs` accepted.

## Data (R2)

| Table | Owner | Fields: width (range) | Layout | Capacity | Lifetime/arena | Producer → consumer |
| ----- | ----- | --------------------- | ------ | -------- | -------------- | ------------------- |
| `Lowered.systf_tasks` | lowering (`lower/systask.zig`) | key `Mir.Inst` (u32) | hash set | one per statement-position `$name` call | the lowering arena | `lowerSysTask` → `call.emitUnregistered` |
| `codegen.SystfSite.task` | codegen (`call.zig`) | bool | column of `systf_names` (AoS, three fields read together) | one per exported call | codegen arena | `systfIndex` → `emitSystfTable` |
| `contract.Systf.task` | the device text | bool | field of a comptime array | `systf_calls.len` | comptime | device → host |
| `analog.n_x` | `src/vpi/analog.zig` | usize (= `Lib.n_u`) | scalar | 1 | `attach` → `detach` | `attach` → `quantityValue` |

Transforms:
- `lowerSysTask: $name statement → Lowered.systf_tasks`
- `emitUnregistered: Lowered.systf_tasks, call inst → SystfSite.task`
- `emitSystfTable: SystfSite → systf_calls[k].task`
- `setPoint: (Analysis?, t, dt, f) → current, t_now, delta, freq`

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `contract` | `@compileError` | `systfError(D)`: every name starts with `$`; a function (`!task`) has no `outs` (§12.22.2) | comptime only | `systf_calls.len` |
| `vpi` `analog.zig` | `ValueError` gains `NoSolution` (`vpi_get_analog_value` reports `NOSOLUTION` through `vpi_chk_error`) | the attached `Lib` is outside data: `quantityValue` checks every slot it would read (`hi_row`, `lo_row` < `n_u`; `contrib_pot` < `n_rows` and its `flow_u` < `n_u`; a flow row needs `n_rows` > 0) before the solution, so a calls-only `Lib` cannot be indexed past its end | runtime, every build mode: one compare per slot per call, cold | the checks are the bounds |

V5's premise, checked against the code: `vpi_get_value` on an analog net
never indexes `Lib.x` (it answers NOVALUE through `value.read`); the only
reader of `Lib.x`, `rows` and `ac_x` is `quantityValue`, behind
`vpi_get_analog_value`. That is where the check sits. Before #83 a stub
attach was in practice refused NOANALYSIS (`have_solution` is set only by
VerA's own `attempt`), so the crash the issue names needed a host that also
ran `run`; the bounds check closes it regardless of order.

No new global mutable state beyond `n_x`, which sits beside the module's
existing `rows`/`ac_x` globals and is reset by `detach`.

## Record (R9)

- No seam added (no rung above 2): `setPoint` is a free function over the
  module's state; the stub is data.
- `docs/host/tables.md` documents `task` and the calls-only host recipe;
  `src/vpi/vpi_user.h` names NOSOLUTION. No `GLOSSARY.md` term; no ADR
  (the abi decision follows the contract's own written rule).
- Archmap and `module_specs` unchanged: no file moved, no import added.

## Goldens

V1 moves the emitted device of every fixture with a user system TASK call:
its `systf_calls` row gains `, .task = true` (after `.outs` when present).
Function-only devices and every other byte are unchanged. V4 and V5 change
no emitted text.
