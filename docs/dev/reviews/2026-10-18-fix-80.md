# Design review: #80, a host-written card value is never checked against its §3.4.2 range

- **Change**: a device with a checkable `from`/`exclude` range publishes
  `checkRange(&model) ?[]const u8`, the first parameter whose value after
  `derive` is out of range. The testbench refuses the card with E0377 (exit
  1); `osdi_dyn` fails `setup_model`/`setup_instance` fatally with the same
  code in its log. The contract knows the decl (optional, additive).
- **Domain skill(s)**: `compiler-construction` (codegen, coded diagnostic),
  `api-design` (a new optional entry point every host can call, AGENTS.md
  §11.8).
- **Hot/cold**: cold. Once per card write, after `derive`; `eval` is
  untouched.
- **Stages run**: R6, R7 (bug fix, §10.1); R1 in brief, since the contract
  gains an entry point.

## Root cause

§3.4.2's value half was implemented only where VerA sees the value at
compile time: `lower/param.zig` `checkParamRange` (E0361), reached for a
`#(...)` override or `--param`. A card value written by a host
(`//! param`, `//! psweep`, an ngspice `.model` line) reached `derive` and
`eval` unchecked. `checkCard` (VD-079) covered Table 9-29 only.

## Boundary (R1)

The caller's code, in any host, after it writes a card:

```zig
if (@hasDecl(D, "derive")) D.derive(S, &model);
if (@hasDecl(D, "checkShape")) if (D.checkShape(&model)) |p| return refuse(p);
if (@hasDecl(D, "checkRange")) if (D.checkRange(&model)) |p| return refuse(p);
```

Same shape as `checkShape`/`checkCard`: one call, a name or null, no
allocation, GPU-safe; the host owns the refusal (flow control is the
caller's). A table of ranges was the alternative; it would make every host
re-implement §3.4.2's union-minus-excludes rule, a second spelling of a fact
the device already holds (§11.8). Retention: none. Granularity: one call per
card.

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `device` `codegen/file.zig` `emitRangeCheck` | `Error` (allocation) | none: ranges are `Lowered.Range`, already folded | the emitted check ships in every build mode (it is the §3.4.2 error, an operating error on host data, not an assert) | one block per parameter with a checkable range |
| `exe` `tb/runner_text.zig` `shapeCheck` | process exit 1 | the card, once per write | n.a. | n.a. |
| `tools/osdi_dyn.zig` `derive` | `false` → `EVAL_RET_FLAG_FATAL` | the card and an instance's own values | message built in a 512-byte stack buffer; on overflow the code alone is logged | n.a. |
| `tools/contract.zig` `validate` | compile error on a wrong signature | comptime | comptime | n.a. |

Implementation-defined choices (when the check runs, which bounds, what a
host gets) are VD-125.

## Test plan (R7)

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| an excluded card value runs | §3.4.2 by hand: r = 2 is excluded → E0377 after the legal r = 3 card's 1 check | fixture (`reject-run`) | merge | `ch03_data_types/range_card_value_excluded_rejected.va` |
| a card value below a `from` runs | r = -1 is in no `from` → E0377 after 1 check | fixture (`reject-run`) | merge | `ch03_data_types/range_card_value_below_from_rejected.va` |
| a blanket refusal (legal values refused) | five legal cards either side of the excluded point, 5 checks | fixture (neighbour) | merge | `ch03_data_types/range_card_value_inside.va` |
| the union/exclude rule, open/closed bounds, int vs real, unfoldable bounds | the emitted text, compared with the rule written by hand | unit | merge | `lib/device/codegen/test.zig` "§3.4.2 checkRange names a card value ..." and "... no checkRange" |
| the OSDI host ignores it | r = -1 on the card → fatal; 2k → 0; an instance's r = 0 → fatal | unit | merge | `tools/osdi_dyn.zig` "a card value outside a §3.4.2 range is fatal ..." |
| the contract drops or mistypes the decl | `MockAll` declares it; `validate` checks the signature | unit | merge | `tools/contract.zig` |

The missing oracle (Principle 19.4): no fixture wrote an out-of-range value
on a card. The two `reject-run` fixtures are that oracle; the neighbour shows
the refusal is the rule and not a blanket one.

What only the gate can confirm: that no existing fixture's DEFAULT or derived
value lies outside its own declared range (the check now runs on every
card). A literal scan of `tests/` (default literal against literal bounds)
found none outside reject fixtures and paramset parameters, whose resolved
values the selection rule puts inside their ranges; derived defaults were
not scanned. The name-list diff decides.

Exit criteria: the three fixtures behave as stated; the unit tests pass;
goldens move in the device text of every device with a literal range (a
`checkRange` block) and in every `.runner.txt` (the `shapeCheck` text);
`tests/harness/sweep.zig`'s device sizes move and are regenerated.
