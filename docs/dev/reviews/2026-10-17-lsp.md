# Design review: `vera --lsp`, M0 and M1

- **Change**: `vera --lsp` serves LSP 3.17 on stdin/stdout. It handles
  initialize, shutdown and exit; full-text document sync; `--lint`'s
  diagnostics published per file URI; and fix-its as `quickfix` code actions.
  The flags come from the command line, then the root's `.vera-flags`.
  `editors/` holds the Neovim and VS Code configurations.
- **Domain skill(s)**: `api-design` (the protocol is a boundary), `zig`.
- **Hot/cold**: cold. There is no profile, benchmark or loop call site, and
  the server runs once per edit, not per element. A full lint per change is
  the known ceiling (`lsp.zig`, `lintAndPublish`'s `ponytail:` comment).
- **Stages run**: R0–R10. It is a new subsystem, scoped to one file. It adds
  no `module_specs` row and no `lib/` change.

## Boundary (R1)

The caller is an editor. The usage code is `editors/nvim/lsp/vera.lua` (three
fields) and `editors/vscode/extension.js` (`new LanguageClient(...,
{ command, args: ['--lsp'] })`). Both run in Neovim 0.11.5 headless: a
diagnostic appears, and its quick fix applies.

- Granularity: one process per workspace, one message per LSP method.
- Redundancy: none. Flags have one spelling, `args.parse`, whether they come
  from argv or `.vera-flags`.
- Coupling: `lsp.zig` reads `vera.compileSourceOpts` and `diag.Bag` only.
- Retention: the server keeps each open document's text, and the URIs it last
  published on. A fix-it travels in the diagnostic's `data`, so `codeAction`
  keeps no state.
- Flow control: the client's. The server only answers or publishes.

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| CLI `lsp.zig` | inferred; `serve` returns OOM/WriteFailed, else an exit status | the header: a missing or bad `Content-Length`, or one past `max_message_bytes`, ends the session with status 1 and its reason on stderr. A body that is not JSON gets -32700; params of the wrong shape get -32602 on a request and are dropped on a notification | no asserts; every check is an operating error | one body per `Content-Length`; at most 64 bag rows per lint |

A panic in the compiler ends the server, and the editor restarts it. That
child-process insurance is deferred until a crash is seen.

## Test plan (R7)

| Bug class | Oracle | Layer | Tier | Harness / file |
| --------- | ------ | ----- | ---- | -------------- |
| a span placed on the wrong line, column or file | `diag.renderJson` on the same bag, as name lists `code file:line:col` (2631 fixtures, 7452 spans) | integration | merge | `lsp.zig` "parity" |
| a UTF-16 column off by a surrogate | a hand count over `aé😀b` | unit | merge | `lsp.zig` "position" |
| framing, encoding negotiation, a fix-it lost on its way to a code action | a hand-derived session transcript (column 21, derived in the test) | integration | merge | `lsp.zig` "a session" |
| a malformed frame or an exit without shutdown | the protocol's exit statuses | unit | merge | `lsp.zig` "exit without shutdown" |
| a URI whose path is percent-encoded or has a drive letter | a hand table | unit | merge | `lsp.zig` "file URIs" |
| `--lsp` beside another mode or an input | the conflict messages | unit | merge | `args.zig` "each conflict" |

The parity oracle is not fully independent: both sides call
`LineIndex.loc`. It sees URI grouping, end clamping and encoding, but not a
`LineIndex` bug.

Seams under test: `serve` over an in-memory reader and writer, and
`diagnostics` over a bag. This is not yet confirmed with the user (below).
Exit criteria: `zig build test` exits 0, and the six tests above pass.

Gate, 2026-10-17: the six tests pass, `test_all` (with the portability guard)
passes, and `zig build check` exits 0. `zig build test` exits 1 on two suites
this change does not compile, `backend` (`orchestrator.zig:390`'s `linkArgv`
assert, after "unrecognized optimization mode: 'fast'") and
`printf_reference` (64 of 129536 conversions differ from this host's
`snprintf`). Their inputs are the same as at `8ac3de14`. The fixture
name-list diff (§0 rule 3) was not run: nothing a fixture compiles changed.
