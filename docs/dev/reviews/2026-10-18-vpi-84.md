# Design review: #84, a per-library systf binding and an instance in HostCall

- **Change**: V2, the state `vpi.analog_run` kept per process for "the"
  attached library (`lib`, `call_obj`, `call_outs`, `outs`, the rows, the
  solution, the walk flags, `arg_values`, `derivs`) moves into a
  `Binding` the host owns, one per device library, optionally owning that
  library's own `Design`; V3, the C hop a library forwards
  `contract.SystfHost.call`/`.out` through (`analog_run.HostCall`/`HostOut`)
  gains the binding (`ctx`) and the host's instance (`inst`), and the
  per-call state the application keeps (IEEE 1364-2005 §27.31 user data,
  the §12.22.2 output record) is kept per instance. Requested by ESPice
  (ESPice#197) after #83.
- **Domain skill(s)**: `api-design` (the `vpi` module's Zig face and its
  C hop to `tb.renderVpiLib`'s library).
- **Hot/cold**: cold. `attach`/`detach` run once per library; `Binding.call`
  once per application call (it already looked a registration up by name
  and walked the call's argument list); `enter`/`leave` add one compare and,
  for a binding that owns its design, two `std.mem.swap`s of a `?Design`
  per call. No profile; no loop over many elements.
- **Stages run**: R1, R6, R7, R9 (a boundary change, §10.1); R2 for the one
  table it adds (`Binding`); R10 by reading.

## Boundary (R1)

The usage code first. An external host (ESPice's shape, #83's R1) compiles
two device modules, `a.va` and `b.va`, each calling a `$name` the user's
VPI application registers, and runs several instances of each. It solves
the circuit itself and binds VerA only to run the application's calltf.

```zig
const vpi = @import("vpi");
const contract = @import("contract");
const DA = @import("device_a"); // vera --emit-zig a.va
const DB = @import("device_b");

// One VPI process: one application, one installed design.
try vpi.open(gpa, &res_a); // A's object model is the installed one
vpi.runStartupRoutines(); // the application registers $a_fn and $b_fn

var bind_a: vpi.analog_run.Binding = .{};
var bind_b: vpi.analog_run.Binding = .{};
// #83's calls-only `Lib` (systf_calls read at comptime, n_u = n_rows = 0);
// its `systf` hook is a no-op: a Zig host calls `Binding.call` directly.
try bind_a.attach(callsOnly(DA), null); // A's calls are objects of the installed design
try bind_b.attach(callsOnly(DB), try vpi.buildDesign(gpa, &res_b)); // B brings its own; bind_b frees it
defer bind_b.detach();
defer bind_a.detach();
vpi.callback.endOfCompile(); // compiletf/derivtf over the installed design (B's ran in attach)

// V3: one SystfHost per device instance; its ctx names the binding and the
// host's instance index, which VerA keys per-call state by.
const Slot = struct {
    b: *vpi.analog_run.Binding,
    i: usize,
    h: contract.SystfHost = undefined,
    fn call(ctx: *anyopaque, k: usize, args: []const f64, p: []f64) f64 {
        const s: *@This() = @ptrCast(@alignCast(ctx));
        return s.b.call(s.i, k, args, p);
    }
    fn out(ctx: *anyopaque, k: usize, j: usize, args: []const f64, p: []f64) f64 {
        const s: *@This() = @ptrCast(@alignCast(ctx));
        return s.b.output(s.i, k, j, args, p);
    }
};
for (a_insts, a_slots, 0..) |*inst, *s, i| {
    s.* = .{ .b = &bind_a, .i = i };
    s.h = .{ .ctx = s, .call = Slot.call, .out = Slot.out };
    inst.systf = &s.h;
}
// ... the same for B's instances, with &bind_b.

// The host's Newton loop: the point once for every library, then eval.
vpi.analog_run.setPoint(.{ .kind = .tran, .stop = tstop }, t, h, 0);
for (a_insts) |*inst| _ = DA.eval(V, xa, &model_a, inst, st);
for (b_insts) |*inst| _ = DB.eval(V, xb, &model_b, inst, st);
```

VerA's own walk goes through the same three calls, with one binding on the
installed design (`tests/vpi_host.zig`):

```zig
var b: vpi.analog_run.Binding = .{};
defer b.detach();
try b.attach(try bindLib(&dl), null);
for (analyses) |a| try b.run(a);
```

Its library (`tb.renderVpiLib`) receives `vera_vpi_systf(ctx, call, out)`
and forwards each `SystfHost.call` as `call(ctx, 0, k, args, n, partials)`:
the library holds one instance.

The signatures, before → after (`vpi.analog_run` unless named):

| before | after |
| ------ | ----- |
| `attach(l: Lib) error{OutOfMemory}!void` | `Binding.attach(b: *Binding, l: Lib, own: ?vpi.Design) error{OutOfMemory}!void` |
| `detach() void` | `Binding.detach(b: *Binding) void` |
| `run(a: Analysis) Error!void` | `Binding.run(b: *Binding, a: Analysis) Error!void` |
| (the C hop only) | `Binding.call(b, inst: usize, k: usize, args: []const f64, partials: []f64) f64` |
| (the C hop only) | `Binding.output(b, inst: usize, k: usize, j: usize, args: []const f64, partials: []f64) f64` |
| `HostCall = fn (k, args, n, partials)` | `fn (ctx: ?*anyopaque, inst: usize, k, args, n, partials)` |
| `HostOut = fn (k, j, args, n, partials)` | `fn (ctx: ?*anyopaque, inst: usize, k, j, args, n, partials)` |
| `Lib.systf: fn (?HostCall, ?HostOut)` | `fn (ctx: ?*anyopaque, ?HostCall, ?HostOut)` |
| `vpi.open` builds and installs | unchanged; `vpi.buildDesign(gpa, res) !Design` builds without installing |
| `attached() ?Lib` | removed (no caller; the host holds `b.lib`) |
| `setPoint`, `analysis`, `time`, `acceptedTime`, `rejectStep`, `failConverge` | unchanged |

The five characteristics:

- **Granularity**: `Binding.call`/`output` are the two halves the device
  already calls (`SystfHost.call`, `.out`), so a Zig host plugs them in
  without the C hop; the C hop stays for a library across a `.so` boundary.
  `attach` takes the design as a value, so building it (`buildDesign`) and
  binding it are two calls.
- **Redundancy**: two doors to one call, on purpose (diagonal): `Binding.call`
  for a host in the same Zig build, `HostCall` for a library that cannot
  take a Zig slice across the C ABI. Both run the same function.
- **Coupling**: the unnamed scope is gone: every per-library table is
  reached through the `*Binding` the caller names, so two libraries can be
  attached, run and called in any order. What stays coupled is what Clause
  12 itself couples (R6 below): the routines take no context, so the
  running call and the analysis point are found, not passed.
- **Retention**: the binding retains the library's tables and solution, as
  before; the host owns its memory (`var b: Binding = .{}`), so VerA
  allocates nothing the host cannot place. The design a binding owns is
  freed by its `detach`.
- **Flow control**: the host's. It calls `setPoint`, then its device's eval,
  which calls back through `SystfHost` into `Binding.call`, which runs the
  application's calltf.

Integration discontinuity: VerA's whole walk (`b.run`), or the host's own
walk with VerA's calls (`setPoint` + `b.call`), for one library or many, on
one code path; the second library costs one `Binding` and one `buildDesign`,
not a second process.

### `abi_version`

Unchanged (6). `tools/contract.zig` is not changed in shape: `SystfHost`
already carries `ctx`, and `Instance.systf` is already a pointer per
instance, so a host could always give each instance its own. What lacked an
instance was the hop behind it, `analog_run.HostCall`, which is the `vpi`
module's interface to `tb.renderVpiLib`'s library, not a published device
table: both halves are built from one tree, and `tests/vpi_host.zig`
rebuilds the library from source on every run. `contract.SystfHost.ctx`'s
doc comment now says it is per instance when the application keeps
per-call state.

A host must change: (1) `vpi.analog_run.attach(lib)` → `b.attach(lib, null)`
on a `Binding` it owns at a fixed address, `detach()` → `b.detach()`,
`run(a)` → `b.run(a)`; (2) a `Lib.systf` hook takes the binding's `ctx`
first; (3) a host that called the `HostCall` it was handed passes that
`ctx` and an instance first, or calls `b.call(inst, ...)` instead.

## Data (R2)

| Table | Owner | Fields: width (range) | Layout | Capacity | Lifetime/arena | Producer → consumer |
| ----- | ----- | --------------------- | ------ | -------- | -------------- | ------------------- |
| `analog_run.Binding` | the host (`var b: Binding = .{}`); `analog.zig` writes it | the per-library state that was module globals: `call_obj []?u32` and `call_outs []u64` (one per `Lib.n_systf`), `outs` map (call k, instance) → `Out`, `rows`, `now_vals`, `prev_react`, `ac_x` (from `Lib.n_rows`, `n_shares`, `n_u`), the walk flags, `arg_values` (object index → f64), `derivs`, `design: ?Design`, `owns: bool` | one struct per library, read together by `attach`/`run`/`call` | one per attached library; its slices sized by the library at `attach` | `attach` → `detach`; `smp_allocator`, as before | `attach` → `run`, `call`, `output`, the §12.10/§12.22 routines |
| `Design.partials` | `root.Design` (written by `systf.buildCalls`) | call object index u32 → `[]const Pair` | hash map | one per call whose derivtf declared partials | the design's (`Design.gpa`), freed by `deinit` | `buildCalls` → `analog.derivative` |
| `Design.userdata` | `root.Design` (written by `vpi_put_userdata`) | (call object index u32, instance usize) → `?*anyopaque` | hash map | one per (call, instance) the application tagged | the design's | `vpi_put_userdata` → `vpi_get_userdata` |

Both maps were `systf.zig` globals keyed by object index; two designs at
once would have shared keys. Their owner is the design the index points
into, so they move there and follow it through `enter`'s swap.

Transforms:
- `attach: Lib, ?Design, installed design → Binding`
- `enter: *Binding → root.design (its own swapped in), active`
- `call: Binding, inst, k, args → calltf's result, partials, outs[(k, inst)]`
- `output: Binding.outs[(k, inst)], j → argument j, its partials`
- `vpi_put_userdata: (running call, systf.active_inst) → Design.userdata`

## Containment (R6)

| Module | Error set | Boundary validation | Check budget (Principle 17.10) | Bounds |
| ------ | --------- | ------------------- | ------------------------------ | ------ |
| `vpi` `analog.zig` | `attach`: `error{OutOfMemory}`, rolled back by `errdefer b.detach()` (an owned design is freed too); `run`: `Error`, unchanged | the `Lib` is outside data, as in #83 (`quantityValue`'s slot checks, now against the binding's own `n_x`/`rows`); a call index k past the binding's table is AMBIGUOUS, as before | `std.debug.assert`s on programmer errors only: `attach` on an attached binding; `detach` of the binding whose call is running; `leave` out of order; `partials.len == args.len` | the binding's slices, sized at `attach` |

The remaining process-wide state, and why each stays:

- `root.design` and the registries (`systf` registrations, callbacks, the
  §12.2 error status): one application per process (§12.33.2's startup
  routines run once), and no Clause 12 routine takes a context, so a
  handle is resolved against the installed design. An owning binding is
  that design for the duration of its own calls and walk (`enter` swaps it
  in, `leave` swaps it back; LIFO, so nesting is safe).
- The point (`setPoint`'s four: analysis, time, step, frequency): §12.7-
  §12.9 take no argument and a process has one simulator time, which a
  host sets once per point for every library.
- `active`, `active_call`, `systf.active`, `systf.active_inst`: the running
  walk or call, set on entry and restored on return. The C routines cannot
  be handed them.
- `installed`: the binding on the installed design, which the routines
  answer for outside any call or walk (a cbEndOfSimulation reading a value
  under VerA's walk). Set by `attach`, cleared by `detach`.

Nothing else: every per-library table is the binding's. Not thread-safe,
as before (`root.zig`'s note).

V3's rule, written where the routines read it: per-call state is kept per
(call, instance) of the running calltf; outside a calltf the routines
answer for instance 0, the only instance VerA's own walk has. `arg_values`
(an argument's value at the latest evaluation, which §12.32.3's sampler
reads from a callback) stays per call: "the latest evaluation" is one
evaluation, whichever instance made it.
