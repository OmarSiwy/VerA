## Confirmed HTML fidelity defects

1. **Figures 5-2, 5-3, 5-5 change circuit topology.** PDF physical pages 114,
   124, 126 draw a gap around the potential-probe `+ p −`/`+ v −` labels.
   Root SVG draws a continuous vertical wire across that gap: Figure 5-2 at
   x=260 and x=480, y=55..240; Figure 5-3 at x=185, y=55..180;
   Figure 5-5 at x=300, y=60..280. These are not harmless layout changes:
   they depict a short across the source instead of an open potential probe.
   Replace with direct source crops rather than further schematic inference.
2. **Figure 5-6 changes the timing illustration.** PDF physical page 140 has
   its event dot inside the tolerance box; HTML places it on the right boundary
   and its accessible description says the curve leaves the box there.
   The source does not require waiting to a box boundary. Its normative prose
   requires the event after the crossing while both tolerances remain satisfied.
   An event inside the box is permitted; do not turn the source illustration
   into an exact chosen delay. The SVG's crossing and left box edge are also
   not exactly aligned. A direct crop restores the original relationships.
3. **§5.4.2 spelling:** PDF line-wrapped `Verilog-AMS` becomes `VerilogAMS`
   in HTML. Retain the hyphen.
4. **BNF terminal distinction is absent.** The selected source syntax pages
   use red literal brackets, parentheses, commas, colons, equals signs and
   keywords distinct from blue/black grammar operators. HTML syntax boxes have
   plain undifferentiated text. For example, Syntax 5-3's vector-index brackets
   are literal while its optional second-net brackets are notation; Syntax 5-7
   mixes literal index brackets with repetition braces. Restore styling only
   after checking each original syntax box; mechanical token equality cannot
   settle this.
5. **§5.7 list hierarchy is flattened.** PDF physical pages 130–131 nests the
   concatenation/filter/hierarchical-assignment restrictions beneath the
   scalar-expression restrictions and the element-type/per-dimension-size
   requirements beneath assignment compatibility. HTML presents each as a peer
   `<p>— ...</p>`. Text remains, but semantic grouping should be preserved.

Figures 5-1 and 5-4 appear topologically consistent on inspection, but their
redraws are not original reproductions. All six source crops below preserve
the original figures, captions and figure-contained code/legends. Figure 5-3's
label `G` denotes conductance; the current SVG accessible phrase “resistor of

- §5.4.1 physical113, flow-access bullet says “Accessing the potential” in its
  second sentence; HTML accurately retains that source wording.
- §5.5.1 physical116 says port references “many not” use hierarchy while
  Syntax 5-3 lists hierarchical port alternatives. Prose restriction and
  broader grammar must both remain visible; grammar acceptance alone is not
  proof a particular port-probe use is semantically legal.
- §5.7 Syntax 5-7 physical130 includes a space inside `array_ variable_identifier`
  and a semicolon in `array_analog_variable_assignment` in addition to its
  enclosing procedural-assignment semicolon. Visually verified source forms;
  annotate, do not silently repair. Source uses `scalar_analog_variable_lvalue`
  then defines `analog_variable_lvalue`; check Annex A before deriving cases.
- §5.8.4 physical133 has confusing “restricted to be used inside ... unless”
  prose. §5.8.1 allows analysis_or_constant_expression; §5.6.1/5.8.4 describe
  constant conditions, and §5.10.3.1 specifically uses genvar expressions.
  Cross-reference §4.5.15 before asserting equivalent condition sets.
- §5.9.1 physical133 says both repeat and while expressions are evaluated once
  before statements, immediately after saying while runs until its condition
  becomes false. Do not infer frozen while conditions from the former sentence.
- §5.10 physical135 says null arguments are not allowed, yet Syntax5-13/16
  includes analog_expression_or_null and §5.10.3.1's physical141 example

  tolerance is supplied, not every empty optional slot.

  `@ hierarchical_event_identifier`. Record the named-event exception/tension
  instead of blanket rejecting legal grammar.

  This conflicts with the surrounding analysis-list name-matching description;
  it is not an HTML cell error. HTML preserves all displayed table entries.
  Keep the anomalous cell visible and unresolved; do not rewrite to zero or
  write an allegedly portable expectation until the authority is reconciled.
- Syntax5-20 physical145 lacks the outer closing repetition brace in
  list_of_event_identifiers. Visually verified; HTML preserves it. The example
  also uses typographic quotation marks. Mark editorial normalizations if made.
- §5.10.4 physical145 describes named-event waiting while §5.10 stresses analog
  detection is nonblocking. Distinguish digital waiting from analog detection;

## Fixture-oracle risks found by reading

Paths below are relative to `tests/fixtures/ch05_analog_behavior/` unless noted.
No compiler defect is newly established here; no fixture execution was done.

### Timer coordinates are not exact normative deadlines

`event_timer_one_shot.va`, `a10_01_timer_nonpositive_period_fires_once.va`,
`a03_04_block_local_is_static_between_events.va` and
`a10_02_timer_enable_resumes_on_grid.va` demand changed state at the nominal
start_time itself. §5.10.3.3 physical142 explicitly allows the default point
at **or just beyond** event time, and zero tolerance selects a suitable tool
value rather than demanding mathematical zero error. The block-local header's
claim that one-shot times are exact independently of timestep choice is false.
These tests can be useful fixed-grid VerA checks but are not portable proof of
the normative timing window. For conformance observations, use positive explicit
time tolerance and inspect state before/after the allowed window, not at its
left endpoint; preserve exact multiplicity at sufficiently later observations.

`a10_timer_breakpoints.sp` and `.expected.json` need the same audit: the SPEC
explicitly describes bit-exact coordinates at nominal timer times despite the
source allowance. These can measure host scheduling choices but must not require
all conforming hosts to choose identical coordinates. No host rerun here.

### Dynamic timer discriminator is overstated

`a10_03_timer_dynamic_period.va` claims a pure start_time+k*period schedule
would already miss the earlier 2ns event after period changes at 4ns. That
does not follow: it can fire at 0,2,4 before/at the change and then8, exactly
the demanded sequence. The next-event-from-last-event interpretation is also
more specific than the cited “latest value” sentence. A change at an off-grid
time is needed to discriminate candidate scheduling interpretations, after
clarifying what §5.10.3.3 actually requires. Current observation still usefully
distinguishes freezing period=2ns, but not every alternative named in its header.

`a10_02_timer_enable_resumes_on_grid.va` re-enables exactly on an original
scheduled event. Its own header admits a frozen schedule could fire at7 and9,
which are exactly expected. Re-enable between grid points, with bounded timing
windows, to distinguish restart/phase shift; review interpolation of the wave
before selecting expected times. The claim that a restarted timer firing8ns
must still show count1 at9ns assumes a host never inserts an8ns point.

### Clause-level rejection quota suppresses a real rule

`a10_11_cross_tolerance_without_direction_rejected.va` explicitly omits the
expr_tol-requires-time_tol rule because “one refusal per clause” is enough.
This directly contradicts the requested rule-level inventory. Add an isolated
`cross(expr, +1, , positive_expr_tol)` rejection plus legal neighboring forms
once directly checked. It is not redundant with the existing missing-direction
case. `event_null_argument_invalid.va` duplicates missing direction using only
DiagnosticsReported and can pass on unrelated diagnostics; pin actual E0517
or its distinctive argument-specific explanation after a direct diagnostic run.

### Positive-looking probes that cannot establish the claimed mechanism

- `event_cross_any.va` is DC/no-event evidence, not evidence of both crossing
  directions. `event_cross_falling.va` has no actual falling crossing and starts
  exactly at threshold, so its alleged wrong-direction discriminator needs a
  strictly negative start and an actual downward transition. Rising and falling
  required firings need independent positive cases.
- `nature_attribute_unsupported.va` checks that ddt remains zero in DC with an
  attribute argument, not that the attribute's numeric value or overridden
  binding was read. Its §11.6.2 citation does not establish VPI relationships.
  Add a direct custom-attribute/abstol value assertion and separate adaptive
  host tolerance-use evidence; retain DC acceptance/noninterference evidence.
- `analog_initial.va` sets a constant gain; repeating initialization each
  evaluation would still pass. Once-per-analysis, sweep dependency re-execution
  and multi-block ordering remain separate behavioral obligations.
- `implicit_fixed_point.va` forces the branch unknown; the later
  `a02_01_implicit_flow_equation_is_solved.va` is the actual free-solution case.
  Existing COVERAGE.md credits the older forced case too broadly.
- `initial_final_analysis_lists.va` says ignoring initial_step's list leaves
  zero, but ignoring filtering and firing unconditionally also sets one. The
  final-step exclusion is useful; it is not symmetric evidence for both lists.
