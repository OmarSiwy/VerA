including rendered physical pages 240–241. Tables 9-21/22 match their source
entries; Table 9-23's page continuation is combined without dropping its g/r

## Source discrepancy FMT-G-001

AMS §9.4.3 invokes C formatting capabilities but calls the precision in
`%10.3g` fractional digits. The public WG14 committee draft
[N1570, §7.21.6.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf),
paragraphs 4 and 8, instead distinguishes significant-digit precision for g/G
from fractional-digit precision for e/E/f/F. Its g/G selection rule also uses
an exponent/precision condition, not an unrestricted shortest-string search.
This primary-source cross-check identifies a discrepancy; N1570 is not claimed
to be the specific C edition normatively incorporated by the AMS LRM. Retain
the original AMS wording and resolve its interpretation before claiming full
g/G boundary coverage. No new g/G expectation was derived from that example.

## Exact-string fixture

`tests/fixtures/ch09_system_tasks/audit_real_format_fields.va` uses the shared
string-output formatter through §9.5.3. Its expected strings are derived in the
header from exactly representable positive/negative halves; no ambiguous
rounding tie or g/G interpretation is involved. N1570 §7.21.6.1 paragraphs 4/8
cross-check the minimum-width padding and e/f digit/exponent conventions.
The fixture requires all its runtime observations through `//! checks`.

Unlike `09_string_formatting.va`, it compares the actual text rather than
scanning it back to a number. Numeric round-tripping cannot detect missing
padding, omitted trailing zeros or an alternative numeric spelling. The new
targeted strict run passes. This is evidence for these string-rendering cases,
not for every output task, stream, precision, locale or solver lifecycle.

A temporary source mutation changes only the first conversion's minimum width
from 12 to 10, leaving the expected string unchanged. Execution then reports
`ok=0` for that padding observation and `ok=1` for the remaining observations.
The process itself still exits successfully, reinforcing that transcript
verdicts, not process exit alone, are the oracle. This is a controlled source
fault, not a compiler mutation; the repository fixture retains width 12.

The subsequent full strict run preserves exactly the preceding nonempty
FAIL/XFAIL name list. The measured report is regenerated by the conformance
script. The new passing row strengthens A's evidence without converting the
static C citation inventory into a behavioral coverage claim.

Negative format/type/argument cases and the full behavior matrix remain open.
No rule group here is marked exhaustively verified and none supplies a new
conformance denominator.

## FMT-WIDTH-001: replacing a deviation-based oracle

The full extracted IEEE §17.1.1.3 (printed pages 281–282, physical pages
311–312) was read on 2026-09-23. It sizes expression output automatically:
decimal fields use spaces instead of leading zeros, other radices retain leading
zeros, and the explicit zero form overrides automatic sizing.

The former `170_display_argument_runs.va` expected minimal output for ordinary
`%d` and bare integer operands. Its own header documented that deviation, but a
passing conformance fixture must not require it. The file now uses explicit
`%0d` where it tests argument-run boundaries and string consumption; it still
passes. Its leading bare expression and unconsumed-operand claims moved to
`audit_integer_default_fields.va`, rather than disappearing from the inventory.

The new positive fixture uses unsigned 12-bit literals, not an assumed host
integer width: their maximum value 4095 establishes four decimal columns and
three hexadecimal columns. Direct string comparisons require the corresponding
spaces or zero digits. Actual execution fails all four default-field
observations and passes the explicit `%0d` control. The strict runner reports
the named XFAIL; no rejection is credited and no expectation was changed to
match implementation output. `//! checks` requires the whole observation set.

`lib/backend/cg_display.zig` documents minimal bare-integer rendering as a
deviation. Its explicit d/radix paths likewise do not automatically populate
field width from the source operand. This checkpoint does not change those
paths. The known limitation is now represented by FMT-WIDTH-001 instead of
being required by a green argument-order fixture. Signed values, variable and
expression widths, other radices and digital output remain separate cases.

The full strict run after this correction exits 1. Its nonempty normalized
FAIL/XFAIL name-list diff adds only
`XFAIL ch09_system_tasks/audit_integer_default_fields.va`; every existing
failure name is retained. The corrected argument-run fixture passes separately.
This newly exposed limitation changes the measured fixture population, not
compiler behavior. The aggregate report is produced only by the conformance
script; no source ambiguity or XFAIL is counted as passing evidence.
