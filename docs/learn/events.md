# Events: cross, above and timer

Every model so far computes its outputs from the present solution, plus the
history `ddt` and `idt` keep. Some behaviour happens at an instant instead:
a comparator flips, a sample-and-hold takes a sample, a counter ticks. An
**event** marks that instant, and an **event control**, `@(...)` followed by
a statement, runs the statement only when the event happens (LRM §5.10).
Events have no duration and carry no data; they say *when*, and the
statement says *what*.

There are two kinds you will use in an analog block. **Global events** are
generated by the simulator at fixed stages: `initial_step` at the first
point of an analysis and `final_step` at the last (LRM §5.10.2).
**Monitored events** are generated when something in the circuit happens:
`cross` when an expression crosses zero, `above` when it rises above zero,
and `timer` when the clock reaches a given time (LRM §5.10.3).

`cross(expr, dir)` fires when `expr` crosses zero in direction `dir`: `+1`
rising, `-1` falling, `0` (or omitted) both. Here `expr` is
`V(clk) - 0.5`, so the event is the clock passing 0.5 V on its way up.

`held` is a plain `real`. A variable keeps its value from one evaluation of
the analog block to the next until something assigns it, so between events
`held` is whatever the last event stored. That is what makes it a hold. A
real variable starts at zero (LRM §3.2), which is the value before the first
sample.

### Where the event lands

The clock rises somewhere between 1 µs and 2 µs, but `held` changes at
2 µs. LRM §5.10.3.1 says `cross` "controls the timestep to accurately
resolve the crossing": a simulator places a time point just after the
crossing, within the tolerances `time_tol` and `expr_tol`. VerA's analog
testbench does not; it steps only the `//! time` points you list, so the
event fires at the first listed point past the crossing. Warning W0750 says
exactly that, and `vera --explain W0750` says how to live with it. The
device itself is unaffected: a simulator that places time points from the
breakpoints the device publishes resolves the event exactly, and
[Mixed signal](mixed-signal.md) shows VerA's mixed-signal runner doing it.

## Once at the start, once at the end, and on a clock

`initial_step` and `final_step` are for work that happens once per analysis:
resetting counters, printing a summary. `timer(start, period)` fires at
`start` and every `period` after it (LRM §5.10.3.3). Together they make
the LRM's bit-error-rate monitor, which compares two bit streams once per
period and prints the error rate at the end (LRM §5.10.2):

```verilog

```

```console

```

The example adds the two counts to the LRM's `$strobe`, so the result can
be checked by hand: the streams differ only at 2 s, one bit in five.

`next_bp` in the transcript is the device's next **breakpoint**: the time it
asks the host to place a point at, here the timer's next tick. The testbench
prints it but does not insert it; this example's grid already lands on every
tick.

## above, and the dc analysis

`above(expr)` is `cross(expr, +1)` with one difference: it can also fire
outside a transient. If `expr` is positive at the end of the initial
operating point, or rises through zero between two points of a dc sweep,
`above` fires; `cross` "will not generate events for non-transient
analyses" (LRM §5.10.3.2):

```verilog

```

```console
{{#include ../examples/events/above.out}}
```

The counts carry over from one sweep point to the next because a dc sweep
starts each point from the variables the previous point ended with (LRM
§4.6.2). That is why `above` counts its one event and keeps counting it.

## Smoothing a step: transition

An event changes a variable instantly. Driving that step straight onto a
node is legal, but a jump in a node voltage is hard on a solver and is not
what a real circuit does. `transition(expr, td, rise, fall)` turns each
step of a piecewise-constant `expr` into a ramp of the given rise or fall
time, after a delay `td` (LRM §4.5.8):

```verilog
{{#include ../examples/events/smooth.va}}
```

```console
{{#include ../examples/events/smooth.out}}
```

The input steps at 1 ns and the output ramps from there over 2 ns. Like
`cross`, `transition` asks the simulator for time points at the corners of
each ramp; on the fixed grid, the corners happen to be grid points.
