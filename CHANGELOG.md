# Changelog: v0.9.0 to v1.0.0, the conformance journey

One short bullet per change, newest first. A fix names its GitHub issue as `(#123)`.

## Unreleased

- Internal cleanup, no change in what VerA accepts or emits: the §9.4.3 format-conversion scanner, the parser's and preprocessor's stack-segment bookkeeping (`deep_stack.Segments`) and the §2.8 identifier-character class each have one copy.
- Tests, no change in what VerA accepts or emits: 28 lowering tests moved from `lib/ir/lower/test.zig` into the `lower/*.zig` file each one tests, and a new VPI test reads `src/vpi/vpi_user.h` and checks that each of the 345 constants the Zig side copies from it still has the header's value.
- Internal cleanup in the digital runtime, no change in what VerA accepts, emits or prints: the interpreter and native executables share one §7.12 switch-path search and one §18.3 `$dumpports` file writer, the interpreter's VPI requests live in `sim/digital/vpi.zig`, `rt.State`'s §17.2 file I/O and held-format scan live in `sim/rt/system.zig`, and the last test-harness import cycle (`harness/devices` and `tests/bench`) is gone.
- Internal cleanup in the device emitter, no change in what it emits: no string compare decides what code is generated (comparisons, stamp signs, float modes, `abs` and the `$` math functions dispatch on enums), one `Gen.poison` marks a refused unit, and the §4.5 operator kernels live in `lib/backend/kernels/ops_kernels.zig`.
- Internal contracts, no change in what VerA accepts or emits: the device emitter, testbench renderers, `osdi_dyn` and the test runner check their own invariants with asserts, and every fixpoint and dominator climb in the setup and unit planners has an iteration bound.
- Generated devices, and the testbenches built from them, no longer name std declarations Zig 0.17 deprecates (`std.fmt.bufPrint` is `std.mem.print`, `std.mem.indexOfScalar` is `std.mem.findScalar`), and the wide-integer kernels drop the unused `zwWord`: the emitted text of devices that print or format integers, capture a `$table_model`, read plusargs or compute a `reg` wider than 32 bits changes.

- Fix: `zig build test -Doptimize=ReleaseSafe` passes again: `tests/status_host.zig` compared a copied `State` with the device's byte for byte, padding included, which LLVM leaves undefined; it now compares field by field. The testbench's `--certify` state check compares a held wide `reg` (`uN`, padded storage) by value for the same reason (#40).
- Internal cleanup, no change in what VerA accepts or emits: four file-level import cycles are gone (`codegen/float/mode` and `plan/jobs`, `sim/digital/plan` and `sim/rt`, `cli/digital` and `main`, `tests/bench` and `harness/sweep`); the generated-shape size table now lives in `tests/harness/sweep.zig`.
- Internal cleanup, no change in what VerA accepts or emits: dead aliases, unused imports and the `proof.prove` wrapper are gone, declarations no other file uses are no longer `pub`, and compiler-side code uses Zig 0.17's `std.mem.find*`/`print` names.
- Fix: a long digital or mixed-signal run no longer grows its memory with every `runUntil` call: the engine's per-event scratch and the pass-switch resolution scratch are kept on the run and reset with their capacity, and an extended dump (`$dumpports`) overwrites each port's last state in place instead of copying it every step (#39).
- VPI: `vpi_remove_cb` on a cbStmt can no longer reach a panic: the statement-hook set is sized when the design opens, so removing a callback allocates nothing; no reachable failure was found, the old `catch unreachable` relied on that by convention (#38).
- Fix: a VPI application that asks vpiReset on every run, or a time callback that registers another at its own time forever, ends the run by name (E1100, after cbError) instead of hanging; a run performs at most 1000 resets (#37).
- Fix: an untimed loop inside one process (`initial forever x = 1;`) is refused by name (E1100, "more than N loop iterations and events at time T") in `vera --run` and in a native executable, where it used to hang; each loop pass counts against the time step's `--event-budget` (#36).
- Fix: a mixed-signal `cross`/`above` whose `time_tol` is below one ulp of the time (a step crossed with `1e-30`) is cut to the two adjacent floats around the crossing and delivered, where the run used to hang re-solving the same point (#35).
- `zig build check` type-checks every root `zig build test` compiles without emitting a binary; `zig build check --watch -fincremental` is the edit loop. `AGENTS.md` adopts the rewrite's design standard: the design review (§10), its rulings for VerA (§11) and `PRINCIPLES.md`.
- `zig build test-vampyre` runs VAMPyRE, the CMC's Verilog-A rule checker, and VerA on the same compact models (self-test probes, VA-Models, cmcqa) and compares hidden state and integer division by a possibly-zero divisor, every disagreement triaged by name; a held variable's `Instance` comment now names why it is held (`event`, `retained`, ...) (#34).
- Fix: an analog operator under a top-level `$port_connected`/`$param_given` condition compiles instead of E0514; §9.19 fixes both at elaboration, so they control analog operators like a parameter (BSIM-SOI 100.1.0's self-heating `ddt`) (#33).
- Fix: a `ddx()` inside a noise power (a channel noise's `gm`) reads its partial in `noisePsd` instead of 0; the noise core is seeded as `eval`'s is when its PSD arguments read a `ddx`, and a host passes `eval`'s family (the testbench and `src/sim/spice` do) (#32).
- `build.zig` builds without a `tests/` directory again (the Nix package and a fetched dependency ship none; `nix flake check` failed), and re-reads the fixture globs on every `zig build` (0.16 s) instead of registering the fixture directories, which made the build runner abort on Windows after a cached-configuration build (#29).
- External digital suites: ivtest, sv-tests and iverilog-diff each have a `TRIAGE.md` that judges every disagreement against IEEE 1364-2005, one row per root cause listing the exact names it covers (a row may now name several patterns). The `external-digital` job passes for the first time. The harness creates upstream's `work/` directory, gives vera the same `-I .` that iverilog gets, and drops iverilog's warning continuation lines from gold files (#25).

- `zig build test` is about 2 minutes shorter: the two nesting stress tests in `lib/root.zig` run 10,000 levels, still past the old 3,000-level stack limit, instead of 100,000 (they were 142 of the `vera` module's 147 s, the critical path); the fixture suite times each compile once outside ReleaseFast instead of five times (#29).
- Fix: an `absdelay` ring's window (`__w`) is restored by `stateCtl(.revert)` like the rest of its state, so a rejected step leaves the instance as it found it; the nightly `--certify` state check failed on every `absdelay` device (#29).
- CI green again: the aarch64 cross build no longer aborts LLVM (a kernels test converted a >128-bit integer to `f64`, which LLVM cannot lower there), `b5_prim_connect_gate_array.va` writes its want as digits, the SSA memo test runs with the dominator skip off, `tests/fixtures/LEVELS.tsv` (the nightly ratchet's level list) is committed, and the conformance summary's `tail` call is portable (#29).

A reported V = 0 there was a probe without `//! solve`, the testbench's documented default netlist, not a solve bug (#29).

- Compile time: lowering is linear in loop generate iterations and flattened instances. The §1.3.1 probe-branch check compared every pair of reads, each `<+` scanned every earlier row, a scope's names were checked pairwise, and SSA climbed every later block (and kept a dense column per place) to read each instance's branch share: 10^5 generate iterations took 3.1 s and 10^6 did not finish in 400 s, now 0.2 s and 2.1 s; 10^4 instances with an `if` each took 5.5 s and 865 MB, now 0.12 s and 64 MB (ReleaseFast `--lint`). A decimal literal of n digits decodes in subquadratic time (10^6 digits: 39.6 s, now 0.25 s). Device text is byte-identical (#29).

A `?:` nested in the true arm of another (`a ? b ? x : y : z`) no longer overflows the parser's stack past a few thousand levels (#29).
- Connect modules on every built-in primitive: an enable gate (`out`, `in`, `enable`), a MOS, CMOS or pass switch (`source`, `drain`, `gate`/`ngate`, `pgate`), a pull source (`out`), an unnamed primitive (`and$1`, `pulldown$1`) and each element of a gate instance array (`a__g[1]__in1`) get the §7.8.4 bridge on a mixed terminal (§7.8.5.1), in the analog compile and the mixed runner alike; a mixed terminal no bridge can take whole (a bit or part of a vector, a primitive in a generate block, a switch array) is refused (E0929) instead of left on the analog node (#29).

- A `reg` wider than 32 bits that the analog context assigns holds every bit: the right-hand side is sized as IEEE 1364-2005 §5.4/§5.5 sizes it (the `reg`'s width joins the context, so `r = K + 1` does not wrap at 32 bits) and a select reads any of its bits (E0329's "reaches above bit 31" is retired). Wide values compute as native integers up to 128 bits and as 32-bit limbs above, at any width, with no allocation on CPU or GPU; devices without such a `reg` are byte-identical (#29).

Devices with 256 or fewer unknowns are byte-identical (#29).
- Frontend limits lifted: source nesting (parentheses, operator chains, `?:`, `begin`, else-if, generate blocks, macro arguments, `` `include ``, library map and SPICE `.INCLUDE` files, SPICE expressions) has no depth cap; the parser and preprocessor recurse on stack segments reserved from memory, and every stage after the parse runs on a stack sized from the depth the parser measured (`deep_stack`). E0241/E0119 now mean only that the system refused that memory. An `` `include `` cycle is refused when a file reopens itself with every macro unchanged (E0125 names the cycle), so a self-include under a changing guard reads.
